0. 这门课讲什么

原视频的定位非常明确：假设你听说过 LangGraph，但从没写过一行相关代码。所以它从 Python 类型注解开始铺垫，用大量类比把概念讲透，再用 5 张”越来越复杂”的图把 LangGraph 的核心机制（节点、边、条件边、循环）全部走一遍，之后才接入真实 LLM，最后用两个完整项目收尾。

讲师原话（值得记住）：”所有这些 AI 智能体库（LangChain、LangGraph、CrewAI、AutoGen）都很棒，但你完全可以自己写几个简单函数来构建 AI 智能体系统，完全不需要任何库。不过我还是推荐用 LangGraph，因为它在控制力和减少样板代码之间取得了很好的平衡。”

3. LangGraph 九个核心概念

📍 视频位置：08:30–18:00

这一节全是幻灯片，是全课的”字典”。讲师的类比相当贴切：

概念 是什么 讲师的类比
State 共享数据结构，保存整个应用的当前上下文 会议室里的白板——大家随时写、随时更新
Node 图中执行特定任务的独立函数，接收状态、处理、返回更新后的状态 流水线上的工作站，各干各的活
Graph 总体结构，描绘节点如何连接和执行 路线图，有路口和分叉
Edge 节点之间的连接，决定执行流向 铁轨，有方向
Conditional Edge 特殊边，基于当前状态决定下一个节点 交通灯（绿/红/黄 = 条件决定动作）
START 虚拟入口，标记流程从哪里开始，本身不执行任何操作 比赛的起跑线
END 流程结束标记，到达即停止 比赛的终点线
Tool 节点内部使用的函数/实用程序（如调 API） 工具箱里的锤子、螺丝刀
ToolNode 特殊节点，专职运行工具，并把工具输出写回 State 流水线上的操作员，操作机器后把结果传回
StateGraph 上面这些的实际容器，你真正交互的第一个对象 乐高积木

最关键的一组区分（讲师专门强调）：

  • 工具 vs 节点：节点是图结构的一部分，工具是节点内部使用的功能。
  • Runnable vs 节点：Runnable 代表各种操作；节点特指”接收状态 → 执行操作 → 更新状态”。
  • 工具 vs ToolNode：ToolNode 是节点，工具是被它执行的东西。

5.2 记忆 Agent

📍 视频位置：103:00–123:00

先看失败案例（课程里特意演示）：5.1 的机器人问”我的名字是什么”→ AI 回答”抱歉，我无法知道你的名字或任何个人信息”。

讲师的定性：”代码中没有任何地方实现了记忆功能。这就是为什么我称这一节为简单机器人——它还算不上真正的智能体，只是一个非常基础的 LLM 封装。”

解法：维护完整对话历史。

要点：

  • Union[HumanMessage, AIMessage] 告诉状态”消息列表里两种类型都可能有”。
  • agent.invoke 发送的是**整个 conversation_history**，不只是当前这一句。
  • 讲师指出这种朴素做法有局限（消息无限增长、无法压缩），更复杂的记忆机制（checkpointer）超出本节范围。

画面里讲师还展示了落盘的 Conversation.txt 对话日志，并指出：即使新消息与历史无关，历史仍被完整保留——这是朴素记忆的实际行为。

6. 进阶：ReAct 工具调用

📍 视频位置：123:00–143:00

这是”基础”与”进阶”的分水岭，也是全课信息密度最高的一节。

6.1 三个新概念

① Annotated 的第二种用法：挂归约函数（reducer）

讲师的解释非常清楚：

“add_messages 是一个 reducer 函数。Reducer 函数的本质就是一条规则，控制节点更新如何与现有状态合并……如果没有 reducer，’Hi’ 会被 ‘Nice to meet you’ 完全覆盖；有了 reducer，就会追加成 ‘Hi Nice to meet you’。”

为什么需要它：ReAct 里一次对话会产生多条消息（用户消息、AI 消息、工具消息），不能总是无脑 append 全部内容。

② Sequence —— 序列类型标注，自动处理列表类状态的更新，避免在节点里写一堆列表操作。

🔴 最大的坑：工具必须有 docstring。

输出会依次看到：工具调用 → 工具消息（结果 7）→ 最终 AI 消息（”3 和 4 的和是 7”）。

讲者的三个精彩演示：

  1. “add 34 plus 21” → 结果 55，并且能看到完整的工具调用过程。
  2. 一次触发多个工具调用：写 “add 34 plus 21 and add 3 plus 4” → 两个工具依次执行（55 和 7）。
  3. “add 12 plus 12” → 模型连续触发 3 次工具调用才收敛。

一个值得记住的概念：

“大语言模型其实不会做算术——它只是靠概率猜下一个 token。但通过工具调用，我们能正确地把两个数加起来。更重要的是，LLM 决定该给每个工具传什么参数：我说 ‘add 3 plus 4’，它会自动拆出参数 3 和 4 交给工具。”

7. 项目实战一：Drafter 起草助手

📍 视频位置：143:00–163:00

7.1 需求与草图

故事：老板说公司起草文件、邮件太慢，要做一个 AI 起草系统，要求：

  1. 人机协作 —— 人类持续反馈，AI 反复修改；
  2. 人类满意时 AI 停止；
  3. 运行快，且能保存草稿。

讲师为什么没直接复用 ReAct 的结构（这是本节最精彩的设计推理）：

“ReAct 里工具总是回到智能体，而不是直接到终点。我们不想要这样——因为 save 工具保存完草稿，流程就该结束了。所以我们要有一条从工具节点直接通向 END 的路。”

7.2 两个工具

三个知识点：

  1. 工具参数由 LLM 填。讲师：”无论你传入什么参数，实际上是大语言模型给这个工具的参数——是后台 LLM 自动提供，不用你操心。”
  2. docstring 决定 LLM 传什么。save 的 docstring 里特意写了”文本文件”，且参数说明提到文件名末尾要有 .txt——模型据此就知道要传什么。
  3. .txt 后缀兜底（健壮性）：”如果文件名末尾没有 .txt 就在后面加上。”

关于全局变量（讲师坦率承认这是妥协）：

“在 LangGraph 中正确的做法是通过一种叫注入状态（Injected State）的方式，但注入状态超出了本课程范围，所以一个变通方法是使用全局变量。……我知道有些人不喜欢，但要用 LangGraph 里更复杂的 Command 和中断机制，代码就得稍微改动。这是入门课程，我们先不考虑。”

7.3 工具级条件边

讲师的讲解：”这里我们有两个工具：update 工具肯定要走继续分支；但如果用的是 save 工具，保存完了就没事了，草稿完成，流程可以结束——这就是结束工具的意义。”

7.4 组装与运行

用 stream 而不是 invoke —— 逐状态打印，人机协作时能实时看到进展。

实际演示流程（非常值得看一遍）：

8.1 准备：PDF → 分块 → 向量库

要点：

  • **temperature=0**：控制输出随机性。讲师：”设为 0 会让模型输出更具确定性。”
  • ⚠️ 嵌入模型必须与 LLM 兼容：”如果你用 OpenAI 模型但嵌入模型来自 Ollama，它们很可能不兼容——一个潜在差异是向量维度。”
  • try/except 是调试辅助：”如果你的 PDF 路径错了或文件找不到，这个 error 就会弹出来。”

分块（chunking）：

  • chunk_size=1000：每块约 1000 个 token；
  • chunk_overlap=200：相邻两块重叠 200 个 token，避免语义在切分处被硬生生截断。

10. 踩坑清单

课程里讲师现场踩过或明确点名的坑，按重要性排序：

  1. 🔴 条件边函数返回的是”边的名字”，不是状态。
    decide_next_node 返回 'addition_operation'，而不是更新后的 state。写错会直接报错。
    绕法：把真正的路由逻辑放在条件边函数里，路由节点本身用 lambda state: state 直通。

  2. 🔴 工具必须有 docstring。
    注释掉 add 的 docstring，图直接不工作——因为 docstring 是 LLM 判断”这个工具干什么”的唯一依据。

  3. 🔴 ChatOpenAI 的导入来源是 langchain_openai，不是 langchain_core.messages。
    （原视频 121 分钟画面上出现过这行错误导入，请以正确写法为准。）

  4. 🟡 add_node 时别传错函数。
    原视频 50 分钟处出现 graph.add_node("second_node", first_node) 的笔误。

  5. 🟡 状态是”就地修改 + 返回”，别写成”替换”。
    顺序链里 final 被两个节点依次写入；如果写成 state['final'] = ... 而非拼接，逻辑就断了。

  6. 🟡 嵌入模型必须与 LLM 兼容，尤其注意向量维度是否一致。

  7. 🟡 RAG 里 temperature=0 用来压低幻觉，并配合”必须引用文档原文”的系统提示词。

  8. 🟡 k（返回块数）要适中，太高引入噪声、太低漏信息，4~5 是甜区。

  9. 🟡 全局变量 vs 注入状态。
    Drafter 用全局变量 document_content 是为了绕开”注入状态”这个进阶特性；生产项目应改用 InjectedState 或 Command 机制。

  10. 🟡 add_conditional_edges 只提供单向边。
    ReAct 里从 tools 回到 our_agent 的那条**回边必须单独 add_edge**。

  11. 🟡 调试就靠 print。
    print('ENTERING LOOP:', state['counter']) 这类语句在循环、条件分支里几乎是必需品。

  12. 🟡 文件名后缀兜底。
    if not filename.endswith('.txt'): filename = f"{filename}.txt" ——防止模型传出没有扩展名的文件名。

12. 学习路线建议

如果你是完全新手，按视频顺序走一遍即可，但建议加上这些节奏：

  1. 第一遍（0:00–1:36）：只看概念和 5 张基础图，手敲每一行代码，不要复制粘贴。
  2. 第二遍（1:36–2:03）：接入 LLM，重点理解 invoke 传的是什么、状态里存的是什么。
  3. 第三遍（2:03–2:23）：ReAct 是全课的技术分水岭，建议把 add_messages reducer 单独吃透——这是 LangGraph 里最容易懵、也最有价值的一个概念。
  4. 第四遍（2:23–3:10）：两个项目挑一个完整复现。建议先做 Drafter（比 RAG 简单，但完整覆盖了工具、条件边、流式三个核心机制），RAG 留作进阶。

学完之后建议立刻做的三件事（课程里没讲，但很重要）：

  • 把 conversation_history 换成 LangGraph 的 checkpointer（MemorySaver），理解持久化状态
  • 给 Drafter 换掉全局变量，改用 InjectedState
  • 把 ReAct 的工具扩充到 3~5 个（减法、乘法、搜索），感受 LLM 自主选择工具
